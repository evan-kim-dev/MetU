## 1. 요약

목표는 화면을 예쁘게 다시 그리는 것이 아니라, **흩어진 기능을 여행 단위로 통폐합해 인지 부하와 조작 수를 줄이는 것**이다.

MetU의 기준 단위를 **기능(AI/지도/가계부/에이전트)** 이 아니라 **여행(Trip)** 으로 고정한다.

사용자는 앱에 들어와 다음을 한다.

1. 여행을 계획한다.
2. 여행 중 지출을 기록·확인한다.
3. 동행과 비용을 나눈다.
4. 정산하고 송금한다.

이에 맞춰 **기능은 합치고, 진입점은 줄이고, 상태 언어는 하나로** 맞춘다.  
능력(OCR·ingest·정산 계산 등)은 유지하되, **사용자가 고를 메뉴·장부·허브의 개수**를 줄인다.

- 입력 경로 여러 개 → **확인함 1 + 가계부 1**
- `/agent` 허브 · TripDetail 가계부 탭 · `TripJourney` → **여행 요약 + 단일 가계부 쉘**
- AI·지도·봇 → **독립 목적지 아님**, 문맥 도우미 / 부가(Phase 8)

## 2. 문제

### 2.1 사용자 관점

- 하단 탭이 `여행 / 가계부(/agent) / 홈 / 멧톡 / 프로필`이라, **같은 여행의 일정·지출·정산이 서로 다른 앱처럼** 보인다.
- SMS·알림·영수증·공유·수동 입력이 각각 다른 진입점을 갖고, **Agent Inbox와 가계부가 별도 장부처럼** 느껴진다.
- `/agent` 허브 · TripDetail 가계부 · `/ledger` 여정이 **같은 돈을 세 길로** 보여 학습 비용이 크다.
- AI 플랜의 예상 비용과 실제 결제액이 한 숫자로 섞이면 신뢰가 깨진다.
- 호스트 6단계·게스트 4단계 스테퍼가 **구조 자체**로 커지면, 역할마다 다른 앱이 된다.
- 기능은 늘었는데 **주 과업(확인·분담·정산)까지 탭·화면이 많아** 사용성이 떨어진다.

### 2.2 현재 코드 사실 (기준)

| 영역 | 현재 | 파일 |
|------|------|------|
| 하단 네비 | 5탭: `/trips`, `/agent`, `/`, `/opod`, `/profile` | `components/ui/BottomNav.tsx` |
| 여행 상세 | `/trips/[id]` — 히어로·예산·`schedule\|ledger` 인페이지 탭. 전용 요약 대시보드 없음 | `TripDetailContent.tsx` |
| 가계부 여정 | `/trips/[id]/ledger` — `TripJourney` + `?step=`. 호스트=`LedgerShell`, 게스트=`Guest*` | `TripJourney.tsx`, `journey-state.ts` |
| 에이전트 허브 | `/agent` → 여행 리다이렉트 (허브 UI 삭제) | `AgentRedirect` |
| 확인함 | `/agent/inbox`(전역·미배정 포함) + `/trips/.../ledger/inbox`(트립 + proposals) | `AgentInbox.tsx`, `LedgerInboxClient.tsx` |
| 데이터 | `agent_events`는 동일 원장·스코프만 다름. `trip_expense_proposals`는 별도 | — |
| 디자인 | 홈/온보딩 레거시 톤 vs 가계부 `mu-*` 이원화 | `docs/design-system.md`, D2/D4/D5 대기 |

### 2.3 하지 않을 것 (Non-goals)

- 커뮤니티(`/board`, `/opod`)·체크리스트 삭제
- 딥링크·URL 계약 파괴 (`/s/[token]`, `/join/[token]`, `/agent`, `/trips/[id]/ledger*`, `?add=`, `?step=` — CLAUDE.md 유지)
- 금액·환율·분담을 클라이언트/LLM이 계산하도록 변경
- 토스 공식 송금 API·네이티브 앱·Gmail 연동
- 기존 마이그레이션 파일 수정

## 3. 목표

### 3.1 제품·IA

1. **한 여행 = 한 공간.** 일정·가계부·정산이 같은 여행 쉘 안에서 이동한다.
2. **장부는 하나.** 입력 경로와 무관하게 확정 거래는 가계부, 미확정은 확인함.
3. **예산 의미를 분리.** 한도 / 예상(플랜) / 실제(확정) / 미정산을 섞지 않는다.
4. **AI는 탭이 아니라 도우미.** 일정·가계부·정산 화면에서 문맥에 맞게 호출하고, 반영은 항상 확인 후.
5. **역할은 권한·기본 랜딩만 다르게.** 호스트/게스트의 화면 트리는 같고, 스테퍼는 “다음에 할 일” 안내로 축소한다.
6. **점진 이전.** 내부 라우트는 유지·리다이렉트하고, 보이는 IA·진입부터 바꾼다.

### 3.2 통폐합 · 사용성 (이 EDR의 핵심 동기)

7. **같은 일은 한곳에서만.** 중복 화면·중복 허브·중복 배지를 흡수하거나 리다이렉트한다.
8. **선택지 축소.** 사용자가 “가계부 vs 에이전트 vs 인박스 vs 여정”을 고르지 않게 한다.
9. **조작 최소화.** 활성 여행 기준 목표 화면까지 ≤ 2탭. 화면당 주 CTA 1개(`BottomCTA` 규칙 유지).
10. **상태 언어 통일.** 자동 기록 / 확인 필요 / 수정됨 — 어디서 보든 같은 배지·같은 의미.
11. **학습 비용 감소.** 호스트·게스트·신규가 같은 지도(요약→일정/가계부/정산)로 설명 가능하게.
12. **성능·유지보수.** 이중 컴포넌트(`LedgerTab` vs `TripJourney`, 이중 인박스) 병합으로 번들·버그 면 축소. (토큰/`mu-*` 유지 — 전면 리스킨 아님)

**사용성 가드레일 (매 Phase 체크)**

| 질문 | 통과 기준 |
|------|-----------|
| 이 기능의 **정식 입구**는 몇 곳인가? | 사용자에게 보이는 주 입구 ≤ 1 (+ 딥링크) |
| 같은 데이터를 **다른 이름**으로 부르는가? | 이름 1개로 통일 (확인함 / 가계부 / 정산) |
| 주 과업에 **불필요한 단계**가 있는가? | 제거·기본값·요약 CTA로 흡수 |
| 모바일 375에서 **가로 스크롤·터치 44px** 깨지나? | 깨지면 머지 차단 |
| 금액·분담이 **두 화면에서 다르게** 보이나? | 서버 단일 소스만 표시 |

## 3.5 기능 통폐합 맵 (Merge / Absorb / Demote)

| 현재 (분산) | 통폐합 후 | 방식 |
|-------------|-----------|------|
| `/agent` 허브 + 여행 목록 + 홈 활성 카드 | **여행** 탭 + **여행 요약** | `/agent` → 리다이렉트·역할 흡수 |
| `/agent/inbox` + `/ledger/inbox` + 홈 미배정 배너 + 쉘 배지 | **확인함** 1개 (전역/여행 필터) | UI·건수 헬퍼 단일화 |
| `agent_events` 대기 + `proposals` 대기 | 확인함 **한 목록** (타입 배지) | 별도 “제안함” 메뉴 제거 |
| SMS / 알림 / 영수증 / share / 수동 | 입력만 다름 → **같은 장부 파이프** | 경로별 앱 메뉴 금지 |
| TripDetail `LedgerTab` + `/ledger` `TripJourney` | **가계부 쉘 1개** | 레거시 탭 흡수·삭제 후보 |
| 호스트 6칸·게스트 4칸 스테퍼 UI | 요약 **다음에 할 일** 1 CTA | 구조 스테퍼 축소 |
| AI 플랜 / 지도 / buddy / insight API들 | **일정·가계부 문맥 도우미** | 독립 “AI 탭” 없음 |
| 초대 링크 + 정산 공유 + 플랜 공유 | UX **초대·공유**, 내부 토큰 분리 | 설정 화면에서 한 섹션 |
| 멧톡·보드·DM | **내 정보 부가** | 하단 탭 제거 |
| (후순위) 단체 수다 + 분담 요청 | **Phase 8 MetU 봇** | 메인 가계부 대체 금지 |

**삭제하지 않는 것:** ingest·OCR·정산 엔진·딥링크·게스트 RLS.  
**줄이는 것:** 사용자가 고르는 목적지·중복 쉘·중복 카피.

## 4. 제안 IA

### 4.1 전역 (하단)

```text
여행          확인함         내 정보
/trips        /inbox (*)     /profile
```

| 탭 | 역할 | 비고 |
|----|------|------|
| **여행** | 목록 · 새 여행 · 진행 중 여행 | 기존 `/trips` + 홈의 “활성 여행” 카드 흡수 |
| **확인함** | 미확정 지출·AI 제안·미배정 | UX 이름. 구현은 `/agent/inbox` 유지 또는 `/inbox` 리다이렉트 |
| **내 정보** | 계정 · 자동화 연결 · 알림 · (부가) 커뮤니티 입구 | `/profile`. 멧톡/보드는 프로필 또는 “더보기”로 강등 |

(*) 홈(`/`)은 랜딩·온보딩 고속도로로 유지하되, **상시 하단 탭의 중심이 되지 않게** 한다. 첫 방문/데모만 홈, 이후는 여행 탭이 기본.

### 4.2 여행 상세

```text
/trips/[id]                    ← 요약 대시보드 (기본 랜딩)
  ├─ 일정                      ← 기존 일정 + AI 플랜/지도/경로
  ├─ 가계부                    ← 확정 거래 + 빠른 수동 입력
  └─ 정산                      ← 서버 계산 결과 · 공유 · 송금 딥링크
```

**요약 대시보드 카드 예시**

| 카드 | 내용 | 이동 |
|------|------|------|
| 헤더 | 목적지 · 기간 · 예산 한도 vs 실제 사용 | — |
| 오늘 일정 | 다음 장소 1~2개 | 일정 |
| 확인이 필요해요 | pending review / proposals / 미배정(이 여행) | 확인함(필터) 또는 여행 스코프 인박스 |
| 가계부 요약 | 실제 지출 · 최근 거래 | 가계부 |
| 정산 현황 | open/stale/completed · 내가 줄/받을 금액 | 정산 |
| 다음에 할 일 | `deriveJourney` 기반 1줄 CTA | 해당 step |

### 4.3 확인함 모델

```text
입력 경로(여러 개)          사용자에게 보이는 상태
─────────────────          ─────────────────────
카드 알림(정책 통과)   →   가계부: 자동 기록됨 (수정·취소 가능)
불확실 알림            →   확인함: 제안 / 확인 필요
영수증·Share Target    →   확인함 → 확인 후 가계부
현금 수동 입력         →   가계부: 즉시 확정
```

| 화면 | 데이터 | 의미 |
|------|--------|------|
| **확인함** | `agent_events`(review/unassigned 등) + `trip_expense_proposals`(pending) | 확정 전 대기열 |
| **가계부** | 확정 지출(ledger expenses) | 단일 장부 |
| **정산** | `settle.ts` 등 서버 재계산 결과 | 확정 장부만 기준 |

**스코프**

- 상단 확인함 = **사용자 전역** (미배정 `trip_id=null` 포함)
- 여행 요약 “확인 필요” = **해당 trip_id** (+ 필요 시 이 여행으로 배정 유도)

같은 목록 UI, 필터만 다르게. proposals는 확인함 한 목록에 **타입 배지**로 합친다.

### 4.4 예산 표시 규칙

| 용어 | 정의 | 출처 |
|------|------|------|
| **예산** | 사용자가 정한 한도 | trip budget |
| **예상 지출** | 항공·숙소·일정 기반 계획 추정 | AI/플랜. 실제 지출 아님 |
| **실제 지출** | 확인·확정된 거래 합 | ledger |
| **미정산** | 동행 간 아직 정리되지 않은 몫 | settle 결과 |

항공을 플랜 예상 비용에 넣었다고 실제 지출로 올리지 않는다. 결제 확인 후에만 실제 반영.

계획 조정은 AI가 **제안 → 사용자 승인**만. 조용한 자동 변경 금지.

### 4.5 AI 역할

- 독립 메신저/채팅방 탭을 핵심으로 두지 않는다.
- 일정: 장소 추가·동선 제안
- 가계부: 분류·분담 해석 (`split-patch` — LLM은 패치만, 금액은 서버)
- 정산: 링크 공유 문안·다음 행동 안내
- 모든 금액성 반영은 확인 UI 후 적용 (기존 `auto_commit`/`review` 정책과 정합)

### 4.6 공유·게스트

사용자 카피: **“초대 및 공유 링크”** 하나로 묶되, 내부는 분리 유지.

| 용도 | 경로 | 권한 |
|------|------|------|
| 여행 초대 | `/join/[token]` | 멤버 claim |
| 정산 공개 확인 | `/s/[token]` | 읽기·본인 분담 조정 범위 |
| 플랜 공유 | `/trips/share/[token]` | 플랜 읽기 |

게스트 **화면 트리**는 호스트와 같고, **기본 랜딩**만 요약 또는 정산으로 연다. (`/join` 직후 현재는 `/ledger` 직행 → 요약으로 바꾸되, CTA는 정산 우선)

스테퍼(호스트 prep/spend/close, 게스트 share/pay/done)는 대시보드 “다음에 할 일”과 배지로만 사용. IA 뼈대로 쓰지 않는다.

## 5. 라우트 매핑 (유지 / 흡수 / 리다이렉트)

딥링크는 **깨지 않는다.** 사용자에게 보이는 이름과 기본 진입만 바꾼다.

| 현재 | 사용자 의미 (목표) | 처리 |
|------|-------------------|------|
| `/trips` | 여행 목록 | 유지 · 하단 “여행” |
| `/trips/[id]` | 여행 요약 | **랜딩을 요약으로 개편**. 일정/가계부/정산은 탭 또는 하위 경로 |
| `/trips/[id]` `?tab=schedule` 등 | 일정 | 기존 일정 섹션 승격 |
| `/trips/[id]/ledger` | 가계부(또는 여정 쉘) | 가계부 탭과 통합. `?step=` · 서브경로 유지(리다이렉트 가능) |
| `/trips/[id]/ledger/settle` | 정산 | 정산 탭의 정식 화면 |
| `/trips/[id]/ledger/inbox` | 여행 스코프 확인함 | 확인함 필터=trip 또는 요약 카드 목적지 |
| `/agent` | (구) 가계부 허브 | **역할 흡수** → 여행 요약 + 확인함. `/agent`는 `/trips` 또는 마지막 여행으로 리다이렉트 후보 |
| `/agent/inbox` | 전역 확인함 | 상단 바 우측. 경로 유지 권장 |
| `/`, 온보딩 | 신규·데모 고속도로 | 유지. 하단 중심에서 제외 |
| `/opod`, `/board` | 부가 | 하단 제거 → 프로필/더보기 |
| `/s`, `/join`, share | 공유 진입 | 유지 |
| `/share-target` | 입력 파이프 | 유지 → 처리 후 확인함 또는 매칭 여행 |

**구현 시 주의:** `TripDetail`의 `LedgerTab`과 `/ledger`의 `TripJourney` **이중 가계부**를 하나로 합치는 것이 선행 과제다. 기준 쉘은 `mu-*` 여정/가계부 쪽을 우선한다.

|------|------|

## 7. 설계 원칙 (엔지니어링)

1. **돈은 서버 순수 함수만** — `lib/ledger/money.ts`, `settle.ts`, `applySplitPatch`. LLM·클라이언트 계산 금지.
2. **LLM은 `lib/ai/gemini.ts`만** — 외부 텍스트는 데이터, `redactSms` 후 전송.
3. **에이전트 쓰기** — `agent_*` RPC + `lib/agent/policy.ts`의 `auto_commit`만 자동 저장. 취소·환불은 항상 review.
4. **멱등** — `idempotency_key`, `(source_event_id, source_index)`.
5. **지역 지도** — `regionOf()` → Kakao/Google. UI는 공급자를 모름.
6. **API 가드** — `guardApi` / ingest / cron. 인벤토리 테스트 유지.
7. **게스트 최종 방어는 RLS/RPC** — UI 숨김은 편의일 뿐.

이 EDR은 위 원칙을 바꾸지 않는다. **바꾸는 것은 배치·이름·중복 쉘 통폐합·사용성**이다. 돈 계산·보안·딥링크 계약은 유지한다.

## 10. 성공 기준

**정성**

- “어디로 가면 되나요?” → **여행 → 일정/가계부/정산 + 확인함** 한 문장.
- 호스트·게스트 **같은 지도**, 차이는 권한·CTA만.
- “가계부랑 에이전트가 뭐가 달라요?” 질문이 **나오지 않는다** (통폐합 성공).

**정량 (측정 가능하면)**

- 활성 여행: 요약 → 목표 화면 **탭 ≤ 2**
- 동일 과업 **주 입구 ≤ 1** (딥링크 제외)
- 하단 탭 **5 → 3**

## 12. 확정 결정 (Accepted)

1. 이 작업의 목적은 **기능 통폐합 + 사용성**이다. 전면 리스킨·카톡형 메인 정산이 아니다.

3. 여행 열면 **요약** → 일정 · 가계부 · 정산. 중복 허브(`/agent` 등)는 흡수.
4. 확인함 = 대기열 1. 가계부 = 장부 1. 정산 = 결과. 쉘·배지·카피도 각각 1소스.
5. AI = 문맥 도우미(`+`). 금액은 확인 후·서버 계산.
6. 스테퍼 = 요약 CTA. IA 뼈대 아님.
7. 딥링크·서버 계산·에이전트 정책 유지. 코어는 Phase 1→7.
8. 커뮤니티 강등. 단체 MetU 봇은 Phase 8 부가(동의→확인함→확정).
